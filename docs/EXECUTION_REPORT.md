## Access and secret boundary

Tailscale 1.102.4 is online with MagicDNS. Existing Serve handlers on 443/3000 and 8787 were inspected and left unchanged; no Funnel entry was configured. Xvfb and shared loopback VNC/websockify facilities exist, but this app creates its own display and does not expose or attach to the shared desktop. The cloud environment-status tool was unavailable and `/etc/codex/network-policy.json` was absent; native read-only host observations are retained instead.

The proxy design follows [Tailscale Serve documentation](https://tailscale.com/docs/features/tailscale-serve). The installed-version [Serve implementation](https://github.com/tailscale/tailscale/blob/v1.102.4/ipn/ipnlocal/serve.go) was inspected: normal HTTP proxying preserves Host, injects HTTPS forwarded protocol and replaces incoming identity headers with authenticated Tailscale identity. Identity is unavailable for tagged nodes/Funnel; the app rejects missing identities and Funnel requests. This source inspection and simulated proxy-header tests support compatibility, **not proof of the unactivated app route**.

Remote requests must arrive from a loopback peer with the exact configured Host, `X-Forwarded-Proto: https` and a hashed allowlisted `Tailscale-User-Login`; by default, a separate panel session is then required for private APIs. Current source supports an explicit `LINKO_PANEL_AUTH=false` opt-out even with `LINKO_PUBLIC_ORIGIN` set: the panel and API need no password/session, while the private identity allowlist is still loaded and enforced. Unset/unrecognized values retain the tailnet password default; local-only mode remains passwordless unless explicitly enabled. Non-loopback binds are always rejected, including passwordless startup. Express global trust-proxy is not enabled. When password protection is enabled, the same identity must match the session.
