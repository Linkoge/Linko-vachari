## Access and secret boundary

Tailscale 1.102.4 is online with MagicDNS. Existing Serve handlers on 443/3000 and 8787 were inspected and left unchanged; no Funnel entry was configured. Xvfb and shared loopback VNC/websockify facilities exist, but this app creates its own display and does not expose or attach to the shared desktop. The cloud environment-status tool was unavailable and `/etc/codex/network-policy.json` was absent; native read-only host observations are retained instead.

The proxy design follows [Tailscale Serve documentation](https://tailscale.com/docs/features/tailscale-serve). The installed-version [Serve implementation](https://github.com/tailscale/tailscale/blob/v1.102.4/ipn/ipnlocal/serve.go) was inspected: normal HTTP proxying preserves Host, injects HTTPS forwarded protocol and replaces incoming identity headers with authenticated Tailscale identity. Identity is unavailable for tagged nodes/Funnel; the app rejects missing identities and Funnel requests. This source inspection and simulated proxy-header tests support compatibility, **not proof of the unactivated app route**.

Remote requests must arrive from a loopback peer with the exact configured Host, `X-Forwarded-Proto: https` and a hashed allowlisted `Tailscale-User-Login`; by default, a separate panel session is then required for private APIs. Current source supports an explicit `LINKO_PANEL_AUTH=false` opt-out even with `LINKO_PUBLIC_ORIGIN` set: the panel and API need no password/session, while the private identity allowlist is still loaded and enforced. Unset/unrecognized values retain the tailnet password default; local-only mode remains passwordless unless explicitly enabled. Non-loopback binds are always rejected, including passwordless startup. Express global trust-proxy is not enabled. When password protection is enabled, the same identity must match the session. Cookies are random, HTTPOnly, Secure, SameSite Strict, host-scoped and expire after eight hours/restart. Password guessing is limited. Missing/malformed access settings fail closed. Mutations require exact Origin plus `X-Linko-Request: 1`; cross-site requests and Funnel headers are rejected in both tailnet modes. No provider-key endpoint exists. The prepared artifact identified above predates this source change; rebuild it before using the opt-out. Permanent `tests/access.test.ts` and `tests/config.test.ts` cover passwordless panel/API access, default protection, environment parsing, allowlist loading, rejected hosts/origins/proxies/Funnel, CSRF and loopback startup enforcement.

This boundary trusts the OS account and loopback. Another malicious local process could forge proxy headers, so this is one trusted owner's host/workspace, not isolation from hostile local tenants. Authorized panel identities share the owner's drafts and one marketplace profile. Tailnet ACL/device restrictions remain an operator responsibility.

A manual browser lease belongs to the panel session, rejects other sessions and concurrent automation, invalidates prepared form state and serializes frame/input operations. Finishing waits for queued operations and preserves the same Chromium context/cookies. Frames and typed login input are not logged or sent to Codex. Main-frame navigation is restricted to observed MyMarket/auth domains; challenge subframes are permitted. Human image clicks use coordinates; automation uses semantic controls only. A button click never asserts marketplace login success.

Private server files are ignored and mode-restricted, not encrypted at rest. No configured project secret or server implementation was found in the client bundle. Pattern scanning cannot prove the absence of all personal data; original credential literals were unavailable for comparison. Native token stores were deliberately not inspected. Offline IndexedDB contains private drafts/previews on the owner's browser and must be protected with the device. API responses/frames/credentials never enter service-worker CacheStorage. Sign-out clears local draft storage.
