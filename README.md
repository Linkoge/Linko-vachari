# Linko MyMarketer

An installable, private PWA for preparing and explicitly publishing MyMarket listings. Choose your main photo, enter the price and description, then review the category and live form before publishing. React editor, Express server, SQLite submission journal, semantic Playwright automation and locally signed-in Codex CLI or Claude Code CLI decisions.

## Run locally

Requires Node 22.13+, pnpm 10, Chromium dependencies, and Xvfb on a Linux server for the private headed browser. The operator signs in to Codex CLI with ChatGPT or Claude Code CLI with a Claude subscription under the application's OS account, according to each saved AI slot. No API key is required or accepted by the panel.

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm browser:install
cp .env.example .env
codex login status
# Only if needed, use Codex's supported interactive sign-in:
codex login
# Or use codex login --device-auth where enabled by your account.
corepack pnpm build
corepack pnpm start
```

Open `http://127.0.0.1:4310`. The default is a trusted local workspace. `pnpm dev` runs the editor with Vite instead of the production shell. Keep the server running for uploads, category discovery and listing work. Do not bind it to a public interface.

Codex uses its own saved ChatGPT sign-in through supported [non-interactive execution](https://learn.chatgpt.com/docs/non-interactive-mode) and [authentication](https://learn.chatgpt.com/docs/auth). Account/model availability and usage limits still apply. This application does not read, export or duplicate Codex authentication tokens. It supplies item text and redacted live page observations through stdin, requests schema-constrained decisions, disables tools and extra agents, and validates the result. Photos are not sent to Codex. Native sign-in and one real structured Codex decision were verified on this host; full authenticated marketplace integration remains unverified.

An operator must activate its dedicated service and HTTPS Serve route following [the execution report](docs/EXECUTION_REPORT.md#manager-activation-handoff). The app stays on loopback port 4310. Tailscale Serve supplies trusted user identity; an app-side hashed login allowlist and, by default, a separate panel password protect the workspace. Funnel/public hosting is unsupported. Tailnet ACLs must authorize the intended owner/device; this implementation does not change them.

In current source, set `LINKO_PANEL_AUTH=false` in the private runtime environment to open the panel and API without the panel login, even with `LINKO_PUBLIC_ORIGIN` configured. Only exact `false` opts out; unset or unrecognized values keep tailnet password protection, and `true` also enables it in local mode. The existing `panel:setup` identity allowlist in `LINKO_DATA_DIR/access.json` remains required for tailnet access; missing or malformed settings still deny access. Setup still records a password hash, but the panel does not ask for that password in opt-out mode. Keep `HOST=127.0.0.1` and use only tailnet-only Tailscale Serve, never Funnel. Startup rejects every non-loopback bind address, including Tailscale IPs. Remote Host must match the configured HTTPS origin exactly, and writes still require that Origin and `X-Linko-Request: 1`; local-only mode accepts loopback hosts. The previously prepared artifact predates this opt-out change and must be rebuilt to include it.

After the operator confirms activation:

1. Connect your phone to the authorized tailnet and open the HTTPS address supplied by the operator. Sign in with your **Linko panel password**, unless the operator explicitly set `LINKO_PANEL_AUTH=false`.
2. Open the **Assistant** window (bottom-right). Enter your MyMarket phone/email and password **once** in its masked form; the server stores them privately (see below). Press **Sign in to MyMarket** or type “sign in”. The assistant signs in inside the persistent automation browser itself. If MyMarket asks for an SMS/email code, the window opens and asks; type the code back into it. No browser driving by you.
3. The signed-in session lives in the persistent browser profile and is reused: later listing runs check the session first and only sign in again (asking for a new code if required) when it has expired. Only if the assistant truly cannot proceed (for example a visual puzzle) does it show **Open private browser (fallback)**; that view is the older click-and-type remote browser under **Connection & setup**, and **Finish login & return** releases it.
4. Use Chrome's **Install app** or Safari's **Share → Add to Home Screen** on the verified HTTPS origin.

The assistant window never shows or returns your password. It is posted once to the server, written to `mymarket-account.json` in the private data directory (mode 0600, git-ignored) and typed into MyMarket by server-side Playwright code. It is never sent to Codex, the draft journal, logs, API responses or the client bundle; one-time codes are held in memory only for the moment they are entered and appear in the chat as `••••••`. Credentials are not encrypted at rest: rely on the OS account and disk encryption. **Remove saved details** in the window deletes the file.

The private browser uses a dedicated display and protected same-origin frame/input APIs. It opens no VNC, debugging or public browser port and does not attach to the shared server desktop. Only one manual login lease or automation run may use the marketplace browser at a time. The lease is bound to your panel session and expires after inactivity.

## Listing workflow

1. Upload one to eight JPEG, PNG or WebP images, up to 12 MB and 40 megapixels each. Images are decoded, rotated and normalized to EXIF-free JPEGs. The first image initializes the cover. **You choose the main photo**; no scoring or photo analysis runs. The selected image is uploaded first.
2. Enter the price and description, plus optional model, condition and city. **Find my category** uses the saved Everyday AI to guide semantic browser actions, searches comparable items and inspects one to three relevant listing breadcrumbs. It does not copy their factual specifications into your item or follow a hardcoded category path.
3. Review/edit the inferred title, category and supplied facts. **Check live listing form** reconciles the current category controls, discovers required fields and asks for genuinely missing facts. Unsupported widgets, uncertain categories, fees or questionable field values stop with an actionable message.
4. Review the actual form values. Publishing is disabled by default. The operator may deliberately set `ALLOW_PUBLISH=true` for real owner use; prepare again after that change. **List on MyMarket → Publish this listing** performs one guarded final submit only after your explicit confirmation.

Automation uses current DOM labels, roles, values, options and transient element handles. AI cannot choose arbitrary selectors, coordinate clicks, credentials, payments or the final publish action. Human clicks in the private login browser are separate from semantic automation. Bounded retries re-observe the page; final publication is never automatically retried. A fresh revision, browser session, field/photo hash and final semantic audit must pass.

A durable SQLite claim prevents repeat publication of identical content/photos across draft IDs. A success receipt requires an observed confirmation and a public listing page with matching title and price. An uncertain outcome becomes **unknown**, including a process interruption; inspect the account manually before any further action. Uncertain attempts are never automatically unlocked or retried.

### Saved records and deleted-listing recovery

Before every final submission, the app saves a private Markdown recipe to `LINKO_DATA_DIR/listings/<draft-id>.md` (default `.private/listings/`). It includes the complete category/section path, exact title and description, price/currency, supplied facts, observed non-private form fields (including optional/default controls), and photo filenames in cover-first upload order. A verified receipt and subsequent monitoring results update that file. SQLite retains the immutable recipe and replacement chain. Keep the **entire private data directory**, including `workspace.sqlite` and `photos/`, in backups: the Markdown alone does not contain the image bytes. Credentials, cookies and account/contact form controls are excluded. Older successful listings are backfilled from their saved draft/review when the server starts; their records can only include fields the older version retained.

The server checks verified listings every **three hours**, including overdue checks after restart. It waits for listing work, manual browser use and an unexpired form review to finish. The **Saved listings** panel provides Markdown downloads, the latest status, original/replacement drafts and pause/resume controls. Records remain available through the private API with the same access and no-cache rules as drafts. Monitoring continues while the server runs, even with the panel closed.

Automatic replacement requires **both** `ALLOW_PUBLISH=true` and `LINKO_AUTO_RELIST=true` in the operator's private runtime environment. The latter defaults to false. Each successfully published item starts with monitoring enabled. **Pause monitoring before marking an item sold or retiring it. Delete ads only through this app**, using **Saved listings → Delete on MyMarket → Confirm deletion**. The app removes the ad with the signed-in browser session and marks it `deleted_by_owner`; monitoring stops permanently. A durable owner-deletion marker is saved before any browser action. An interruption or uncertain deletion becomes **attention** and can never re-list or resume monitoring. Inspect the account if attention is needed; the app never retries that deletion blindly. Deleting directly on MyMarket bypasses this marker, so a public 404 would look like a marketplace deletion. Resume resets the deletion evidence. This change implements the capability; it does not enable or deploy it on the live host.

Recovery requires two HTTP **404/410** responses for the exact saved public URL, separated by at least **one hour** (first missing response → confirmation one hour later). Regular checks remain every three hours. Before counting any 404/410, an independent browser tab must load the MyMarket home control successfully (HTTP 200, recognizable content, no challenge, login or error shell). A failed control means **unavailable**, resets missing evidence and never triggers re-listing. All checks are script-only and make no AI calls. Timeouts, redirects, login pages, browser challenges, server errors, changed content and ambiguous 200 responses reset the evidence and never trigger publication. Some MyMarket removals may use a 200 error shell; those are reported as inconclusive until their actual behavior can be verified. The monitor replays learned semantic browser steps for the exact saved category path, fields, text, price and cover-first photo order. Field states, required fields, form text (including category/fee notices), photo order, duplicate claims and the final control are audited deterministically, and the old URL plus its control are rechecked immediately before the one guarded submit. An unchanged recipe uses no AI, including receipt verification. If a control or form changed (or an older recipe has no learned steps), **Fix-it** repairs that run with the same saved recipe. Successful preparation saves updated semantic control signatures and steps in the private recipe; receipt confirmation text is learned after a verified submission. Delete uses the same script-first approach and saves successful learned delete controls in SQLite. AI never submits or repeats a final publish/delete click; it only proposes semantic targets or interprets an already-submitted receipt. Unknown facts, uncertain model responses, provider errors and uncertain clicks stop with **attention**. No blind publish retry follows. Existing field, fee, photo and publication audits still apply. It neither searches for comparable products again nor invents missing fields. The replacement gets its own record and future checks; the old record is retired.

Unknown new form requirements, uncertain Fix-it decisions, sign-in issues, missing photos, interrupted preparation and uncertain submissions stop automatic recovery for that item and show **attention**. Open its replacement draft and inspect the MyMarket account. A blocked draft can be corrected and explicitly prepared/published after review; an unknown publishing attempt remains locked. Neither restarting the server nor resuming monitoring retries such an attempt. Fixture tests cover confirmed deletion through a verified replacement; no live listing was published or removed for this feature.

## Settings: AI and Telegram

**Saved listings** stays visible even before the first verified publication, with an empty history message when there are no records.

Open **Settings** in the top bar on desktop or mobile (or **Connection & setup**). The **AI** section has exactly two slots:

- **Everyday**: category choice and field matching for new listings. Default: Codex CLI, `gpt-5.4-mini`, low reasoning.
- **Fix-it**: only after a saved script fails because the page changed. Default: Codex CLI, `gpt-5.4`, high reasoning.

Each slot saves its provider (Codex CLI or Claude Code CLI), exact model name and low/medium/high effort. The picker follows the host's Linko Bot Manager: three-column model buttons with a thinking/effort row underneath each provider. Choose a model to select its provider; only that provider's effort row is enabled. Model buttons highlight the saved choice; the selected effort uses accent text. Arrow keys and Home/End move focus within a row; Enter/Space selects. The compact layout works on desktop and narrow phones.

Every model or effort selection saves immediately. The highlight changes only after the server confirms the saved pair; both slots are disabled while saving. Failed or lost responses reload the saved settings. If that refresh also fails, choices are hidden until **Retry settings** or reconnection succeeds. Offline controls are disabled. Closing/reopening or reloading shows the same saved choices used by jobs; there is no separate AI Apply step or unsaved selected model.

The family buttons are presentation suggestions: Codex Luna (`gpt-6-luna`), Sol (`gpt-6.1-sol`), Astra (`gpt-6-astra`), and Claude Haiku/Sonnet/Opus (CLI aliases `haiku`, `sonnet`, `opus`). Unlike the manager's provider catalog service, this app does not discover account models or automatically advance family versions. Access is checked by the actual decision. Existing defaults and any other saved exact model ID remain visible as a pressed button; nothing is migrated by opening Settings. **Use another model** lets you explicitly choose a provider and enter an exact ID supported by your account. This input is a draft until **Save model** succeeds, retaining the slot's current effort. Selecting a model retains the saved effort; unsupported effort fails on use without substituting a different model or provider.

Settings live atomically in `LINKO_DATA_DIR/settings.json` (0600), not environment variables. `LINKO_CODEX_MODEL` is no longer used. CLI executable paths (`LINKO_CODEX_BINARY`, `LINKO_CLAUDE_BINARY`) and the bounded decision timeout (`LINKO_CODEX_TIMEOUT_MS`, default 150 seconds) remain operator runtime options. Missing CLI, missing local subscription sign-in, inaccessible model or unsupported effort fails clearly, never switching providers. The picker reports CLI installation/sign-in readiness; model access is verified by the actual decision. If needed, the operator runs `codex login` or `claude auth login` outside the app. No provider API keys are accepted or passed to either CLI.

Codex uses [schema-constrained non-interactive execution](https://learn.chatgpt.com/docs/developer-commands?surface=cli). Claude uses [print mode, JSON schema, explicit model/effort and disabled tools](https://code.claude.com/docs/en/cli-reference), with no session persistence, no project/user setting sources, disabled hooks and no MCP servers. Keep both CLIs current enough to support these flags; unsupported versions fail rather than changing providers. Both transports redact input, discard CLI errors, validate JSON and kill the process group at the timeout. Account tokens are never read or copied. Photos are never supplied to AI.

In **Telegram**, create a bot through **@BotFather** (`/newbot`), paste its bot token, and save. Open that bot and press **Start**, then send it a message. Use **Detect chat ID** to read private-chat IDs from `getUpdates`; choose yours and save again. **Send test message** verifies the saved connection. If Telegram returns no chat, message the bot again; a bot already using a webhook may need a separate bot for this app. **Disconnect Telegram** removes the saved settings.

The bot token is write-only in the UI, registered for redaction, never included in API responses or logs, and stored only in the private settings file outside Git. Notifications cover confirmed marketplace deletion, successful re-listing with its new URL, script failure/Fix-it start, successful AI repair, and attention. Delivery is best effort with four-second timeouts, bounded response size/concurrency and no automatic delivery retries; notification errors never block monitoring. Test/detection buttons report delivery/setup failures without exposing raw Telegram responses. Keep settings, SQLite, photos and browser state together in private backups.

## Privacy, offline use and limitations

Secrets, cookies and drafts remain in the ignored server data directory (default `.private/`, mode 0700; file creation mode 0600). MyMarket credentials live in `.private/mymarket-account.json`, panel password/allowlist hashes in `.private/access.json`, and browser cookies/sessions in `.private/browser/`. If `LINKO_DATA_DIR` is set, these paths are relative to that directory; keep it private and outside tracked assets.

For local environment credentials, copy the empty placeholders from `.env.example` into the ignored `.env` in the workspace root and restrict it with `chmod 600 .env`. The server loads this file through `dotenv`; exported environment variables take precedence. `MYMARKET_PHONE`/`MYMARKET_PASSWORD` are an optional server-only seed when there is no valid saved vault; the assistant window is the normal way to supply them. Keep existing private files locally when updating the checkout. Never put credentials in examples, evidence, screenshots or source code. Codex and Claude Code keep their own sign-ins outside this repository; the application does not copy them.

`pnpm test` includes a permanent index check that rejects tracked environment files, private keys, credential JSON and cookie/token/session data, even if force-added or missing from the working tree. Only `.env.example` and `runtime.env.example` are allowed environment templates, with empty credential fields. `pnpm security:check` also scans reachable git history without printing credential values. If a real credential is found, retain its local copy, remove it from the index with `git rm --cached -- <file>`, and rotate it with the service provider. Removing it at HEAD leaves historical exposure intact; do not rewrite history or force-push as part of this cleanup.

Runtime files are not encrypted at rest. Use a trusted OS account and encrypted disk. This is one owner's workspace and one marketplace session; authorized panel users share it. Loopback is a trusted OS boundary: unrelated local processes must also be trusted. Remote access requires the exact configured HTTPS origin, trusted loopback Tailscale proxy, allowlisted identity and CSRF checks. A secure panel session is also required unless `LINKO_PANEL_AUTH=false` explicitly disables the panel password; passwordless users share the trusted workspace and manual-browser lease. Tagged devices without user identity fail closed.

The PWA caches the public shell and saves draft text/previews in IndexedDB. Private API responses, browser frames and credentials are not cached by the service worker. Offline text edits require explicit save after reconnecting; uploads and publishing are never queued offline. Panel sign-out clears local draft storage. Anyone using the same unlocked browser/device can access its offline drafts; keep the device private.

Cloudflare: the earlier 403 came from automation fingerprints (the default `HeadlessChrome` user agent, like curl's default agent). A headed, persistent real-Chromium profile on the private Xvfb display with the automation flags removed is admitted (HTTP 200); headless is only admitted with a normal user agent. The browser layer also waits out interstitials and dismisses MyMarket's cookie/promo overlays. See the [execution report](docs/EXECUTION_REPORT.md#agent-driven-sign-in-and-cloudflare-findings) for exactly what was verified live. MyMarket signs in on `auth.tnet.ge` (email or phone + password, invisible reCAPTCHA). **Verified live with the owner's real account (2026-10-15):** email + password sign-in succeeded with no SMS/email code, the session persisted in the browser profile and was reused on the next run, and a sample listing was prepared up to the pre-publish review (category found from live comparables, full category path selected, condition/price/title/description/required dropdowns filled from the draft, three photos uploaded cover first and verified in order) without clicking publish. Sign-in passes through single-sign-on hops on sibling auth hosts (`auth.myauto.ge/?AccessToken=…`), which are allow-listed; the live form uses react-select dropdowns, `fast-option` rows, hidden button-styled radios (selected state is an `active` class) and an uploader that shows a multi-file selection out of order, so photos are uploaded one at a time and the gallery order is checked. A real submission receipt remains unverified; the app must still discover new required attributes during use and fail closed. Video upload support could not be established from public material or an authenticated uploader; stage one is photo-only, with video an optional later extension.

## Automated deploy

The scripts in `deploy/` are argv-callable (bash inside) and are configured through environment variables, never arguments. The service runs from `~/.local/share/linko-mymarketer/releases/current/app`, where `releases/current` is a symlink switched atomically to `releases/<UTC timestamp>-<commit12>/`. Runtime configuration stays in `~/.config/linko-mymarketer/runtime.env`; the scripts read only its `LINKO_DATA_DIR` path and never print it. The unit derives `LINKO_RELEASE_ID` from the real release directory, so `/api/health` reports the deployed release.

| Script | Environment | Effect |
| --- | --- | --- |
| `deploy/backup` | `DEPLOY_BACKUP_DIR` | Writes `record.env` (active release, from `current` or a legacy pinned unit; data path; time), copies the private data directory to `data/` and the installed unit to `unit.service`. |
| `deploy/deploy` | `DEPLOY_REPO`, `DEPLOY_COMMIT` | `git archive` of the commit into a new release, `pnpm install --frozen-lockfile` and `pnpm build`, installs the release's unit file, `systemctl --user daemon-reload`, atomic `current` switch, `systemctl --user restart linko-mymarketer.service`. A failed build removes the partial release and changes nothing live. Keeps the newest 5 script-built releases (`DEPLOY_KEEP_RELEASES`), never the active or previous one and never hand-prepared releases. |
| `deploy/health` | optional `DEPLOY_HEALTH_URL` (default `http://127.0.0.1:4310/api/health`) | `curl --max-time 10` retried for up to 60 s; any HTTP status below 500 counts as answering. |
| `deploy/rollback` | `DEPLOY_BACKUP_DIR` | Points `current` back at the recorded release and restarts. Data is kept as is; `DEPLOY_RESTORE_DATA=1` also restores the backed-up data directory (the replaced one is kept beside it as `*.pre-rollback.<time>`). |

Other optional variables: `LINKO_DEPLOY_ROOT`, `DEPLOY_RELEASES_DIR`, `DEPLOY_UNIT_DIR`, `DEPLOY_ENV_FILE`, `DEPLOY_DATA_DIR`, `DEPLOY_SERVICE`, `DEPLOY_PACKAGE_MANAGER` (default `corepack pnpm`), `DEPLOY_STEP_TIMEOUT_SECONDS`. Deploy refuses a commit whose unit file does not run from `releases/current/app`. The data copy is a plain `cp -a` of the live directory, taken before the restart. `tests/deploy.test.ts` exercises all four scripts in disposable directories with fake `systemctl` and package-manager shims.
